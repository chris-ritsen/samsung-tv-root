Samsung TV root, untethered

How a Samsung Tizen TV re-acquires root by itself at every power-on — no host computer, no app squat, no visible window — through a stock Samsung service hook, a signed gawk interpreter, a token-gated sdb bridge, and a Magisk-style module system.

root at uptime ~10s Tizen 6.5 · armv7l QN55Q60B / T-NKLBAKUC-1720.7 no Developer Mode dependency rollback = one file copy

01The boot chain

Every step below runs on the TV. The host computer is not in the chain — it only connects later, optionally, for maintenance.

power-on → systemd starter.targetvendor
Tizen boot sequence begins.
│
AT-HUB.servicevendor
A stock Samsung unit symlinked from starter.target.wants. No User= setting → runs as uid 0, SMACK System::Privileged. Its ExecStart is /opt/etc/parseinfo.sh & — a script on the writable, persistent /opt vdfs.
│
#!/usr/bin/gawk -f — our hook replaces /opt/etc/parseinfo.shours
Preserves the vendor behavior 1:1 (writes __REPO__MODEL__ to /proc/target_version), then starts the runner. Stock bytes are backed up first and verified by SHA-256.
│
runner.sh — proof, labels, boot-settle gateours
Writes the SELFROOT-PROOF uid=0 evidence file, sets SMACK labels on the evidence directory, waits for the systemd job queue to drain, then runs every enabled module.
│
module loop → bridge, masks, watchdogsresult
Re-creates the bridge unit in tmpfs, masks/stops Samsung's telemetry and ad daemons, launches supervised watchdogs — idempotently, every boot.
Why gawk? Kernel UEP excludes #! scripts from its target types, so systemd can exec the hook — but sh/bash refuse to load unsigned script files (the stock parseinfo.sh carries a Samsung ##UEP signature trailer for exactly that reason). Signed /usr/bin/gawk is not linked against libkUEPUser.so, so it reads the hook as plain data, and its system() shells out without script-file arguments. A plain #!/bin/sh replacement execs — then exits 1 having run nothing.

02The one-time foothold

Persistence was installed from a root session obtained with upstream's archive-root route (credit: chris-ritsen):

A crafted package name in an allowed installer call yields a shell as uid 901(sdk).
│

A per-run mount namespace and Samsung's signed-archive launch path yield uid 0 — no firmware files modified, everything volatile and verifiable.
│

From then on, the TV roots itself at every boot; the foothold is only needed again after a /opt wipe.

03What runs at every boot

The module system is Magisk-style: each module is a directory under /opt/usr/share/selfroot/modules/ with a boot.sh, a disabled flag, and per-module logs. The runner honors UI/host enable/disable overrides and skips disabled modules.

  • at-hub-persistence — the vendor-hook installer; owns /opt/etc/parseinfo.sh, backup + rollback.
  • bridge-service — token-gated sdb relay as a headless Restart=always systemd service; the host CLI works while Developer Mode Host PC IP stays 127.0.0.1.
  • samsung-telemetry-off — masks data-service/pushd/bms/appbinary-manager, plants vendor opt-out switches, kills ACR/voice/Bixby/SSO/CIS respawns, supervises a 30s watchdog.
  • ad-telemetry-daemons-off — masks and stops the ad/analysis daemons (adagent, pisa, canalysis, context-aware, contents-recognition).
  • sw-update-off — keeps the firmware update path inert so the pinned exploit surface stays pinned.
  • cec-key-passthrough — stops the TV eating CEC remote keys so HDMI-CEC devices (e.g. a Fire TV stick) respond instantly.
  • 00-canary — boot-order canary + evidence markers.

04Three eras of the chain

era 1 · host-driven

Upstream toolkit

Volatile root reacquired from a computer over sdb at every power-on. Solid, but needs a host on the LAN.

era 2 · app squat

Boot agent in com.samsung.tv.ghservice

A .NET agent replaced the preinstalled Gaming Hub service app and self-rooted at boot. Worked — but the platform surfaced its window over HDMI sources, and the squat meant package-DB and manifest surgery.

era 3 · vendor hook

AT-HUB.service + gawk

Root at boot via a stock Samsung service whose ExecStart lives on writable /opt. No window, no package DB, no app squat — and ghservice is back to stock bytes. Shipped 2026-11-06.

Era 3 is what runs today. The retired squat agent's source and its full write-up remain in the repo for other models where no writable boot-executed script exists.

05Safety profile

  • Read-only rootfs untouched; everything persistent lives on the rw /opt vdfs. Nothing hooks the boot chain or firmware image.
  • Stock parseinfo.sh backed up byte-exact before replacement; rollback is cp + reboot.
  • ghservice restored to stock: dll, runtimeconfig and manifest byte-verified against the pre-squat tarball; package DB row reverted.
  • Developer Mode survives reboots independently, so the sdb foothold remains a recovery lifeline even if the hook is wiped.
  • UEP is never disabled system-wide; unsigned execution flows only through the documented stdin and signed-interpreter paths.
  • A firmware update that reinstalls parseinfo.sh simply returns the TV to stock — re-run the installer from any root session.
